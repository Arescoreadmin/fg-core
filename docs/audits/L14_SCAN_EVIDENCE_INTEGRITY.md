# L14 Scan Evidence Integrity and Provenance Audit

**Audit ID:** L14-FIELD-SCAN-DEEP-AUDIT-001
**Date:** 2026-11-06

Evidence chain completeness and defensibility assessment for each scanner.

---

## Evidence Chain Architecture

All scan results flow through the following chain:

```
Scanner runner → raw payload → FaScanResult (db) → FaVerifiedTarget (for target-based scans)
              → FaScanAuditEvent (every lifecycle event)
              → FaNormalizedFinding (findings extracted)
              → FaEvidenceLink (engagement-level link created automatically)
              → Evidence lifecycle lock (collected → locked → legal_hold)
```

The H15 evidence lifecycle enforces: collected evidence is mutable; locked evidence (applied at QA approval) blocks all mutations; legal hold supersedes locked and also blocks deletion.

## Evidence Lifecycle Enforcement (H15)

All FaScanResult, FaFieldObservation, FaDocumentAnalysis, and FaEvidenceLink records are subject to H15 lifecycle enforcement:

- `collected` state: mutable
- `locked` state: applied in bulk at QA approval; blocks create/update/delete
- `legal_hold` state: operator-applied; blocks all mutations including deletion; audited
- `assert_mutable()` guard called before every mutation
- `lock_evidence_for_engagement()` bulk-locks at QA approval
- 31 lifecycle tests passed (1 skipped) in `tests/test_h15_evidence_lifecycle.py`
