## Defects Found

### D-T8-001 — /health does not verify database connectivity

**Severity:** High
**Finding:** The `/health` endpoint returns HTTP 200 when `DATABASE_URL` points to an
unreachable host. Railway's health probe uses `/health` exclusively, so a DB connectivity
failure is undetectable by the platform and would not trigger a crash or alert.
**Impact:** A DB misconfiguration would silently pass health checks and only manifest
as failures on the first authenticated API call, with no automated recovery.
**Follow-up:** Add a lightweight DB ping (`SELECT 1`) to the `/health` response. Return
503 if the ping fails within a short timeout. Track as a separate hardening PR.

### D-T8-002 — Runbook CLI command for per-deployment rollback is invalid

**Severity:** Low
**Finding:** The T8 runbook documented `railway redeploy <DEPLOY_BEFORE> --service api`
but the Railway CLI does not accept a positional deployment ID; `railway redeploy` always
redeploys the latest deployment.
**Impact:** Added approximately 7 minutes of delay during this drill while the CLI syntax
error was identified and the dashboard path was found.
**Fix:** Runbook updated in this commit. Correct CLI fallback: restore the correct
variable value with `railway variable set DATABASE_URL=<correct> --service api`.

### D-T8-003 — Runbook audit chain URL and auth method are incorrect

**Severity:** Low
**Finding:** The T8 runbook specified `GET /api/core/audit/chain/verify` with an
operator-level `X-API-Key` header. The actual endpoint is `GET /forensics/chain/verify`
and requires a tenant-scoped API key with `forensics:verify` scope (not an env-level
key). The `FG_API_KEY` Railway variable is not a valid credential for this endpoint.
**Impact:** Automated audit chain verification was not possible during this drill.
**Fix:** Runbook updated to specify the correct path and note that verification requires
a tenant credential; for drills, use the console forensics view (covered in T9).
