## Runbook Gaps Identified and Patched

### Gap 1 — Locked evidence requires unlock before link/scan-result deletion

- **Trigger:** `fa_evidence_delete_guard()` fires on `fa_evidence_links` and `fa_scan_results` when referenced evidence has `lifecycle_state = 'locked'`
- **Observed:** Steps 1 and 4 errored; 3 `fa_scan_results` rows remain orphaned (no parent `fa_evidence` row, contain no PII — scan parameters only)
- **Fix:** Added Step 0 to runbook: set `lifecycle_state = 'pending_purge'` on locked evidence after confirming report delivery, before executing Steps 1 and 4
- **DPA posture:** Section 2.1 already authorizes purge of locked evidence after report delivery — Step 0 operationalizes that authorization

### Gap 2 — fa_evidence_report_links is an append-only audit ledger

- **Trigger:** `append_only_guard()` fires on DELETE — this is by design
- **Observed:** Step 3 errored immediately
- **Fix:** Step 3 removed from deletion procedure. `fa_evidence_report_links` is subject to 7-year audit retention (retention policy §Tier 4). DPA client-data purge does not override audit retention obligations. The link records contain no client PII — only evidence IDs and report IDs.
